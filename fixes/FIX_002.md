# FIX_002 — Source preservation, semantic review and actionable clarifications

**Date:** 21 September 2026.

**Status:** Proposed phased rollout; implementation and live validation are outstanding.

**Scope:** Remediate the observed false-conflict → unsupported-review → unnecessary-clarification sequence through existing owners.

This plan follows an end-to-end inspection of the retained run, requests,
responses, production events, published artifacts, current implementation and
governing contracts. It does not amend those contracts or approve model calls.
[FIX_001](FIX_001.md) and [IMP_001](IMP_001.md) retain historical delivery evidence;
this document records the follow-up sequence, not another source of runtime policy.

## 1. Required outcome

Generate a source-grounded business specification when the references establish
sufficient intent. Ask the user only for an identifiable missing decision. Treat
meaning lost through extraction or reconciliation as a candidate defect, with
repair only through established authorization and complete dependent rebuilding.

Preserve these boundaries throughout the rollout:

- Unrepairable JSON/schema failure terminates with an error and no new `spec.md`,
  including when clarifications are already open.
- A genuine clarification pause may publish a validated incomplete specification;
  it cannot record completed specification authority or run completed-spec grading.
- Open Spec clarifications prevent Plan; open Spec or Plan clarifications prevent Tasks.
- References and accepted answers establish business intent. Principles supply policy
  evidence; they cannot invent, erase or replace that intent.
- No greeting, timestamp, filename, model name or fixture-specific continuation rule.
  The illustrative specification discussed with the user is not a golden document.
- Preserve configured JSON composition, full validation, native provenance, local
  retry identities and actual-token accounting against the execution budget.
- No new fixer agent, semantic keyword detector, schema registry, evidence store,
  retry engine, Markdown repair path or automatic provider/model fallback.

## 3. Causal findings and limits

### Confirmed architectural contributors

- **One business claim carries all three behaviours.** The false conflict therefore
  strands startup, greeting and date/time together. This establishes the impact of
  the chosen granularity, not that grouping caused the model's conflict judgment.
- **Candidate labels also restrict diagnostic evidence.**
  `specification_support_evidence.eligible` excludes conflicting claims from
  feature-level evidence, including `candidate_omission`; `admit` applies that
  eligibility check to every finding. Yet `source_omission.validate` requires the
  exact conflicting claim set for a `reconciliation_conflict` loss location.
  Source-only evidence cannot satisfy that join. Original source is available,
  but a correct feature-level diagnosis can still be inadmissible. D3 below
  addresses this gap without making conflicting claims valid positive provenance.
- **The review contract has an initial schema/native mismatch.**
  `support.schema.json` makes `question` optional for every initial/insertion
  finding. Native `questionRequired` requires it for three negative decisions and
  forbids it for others. Selected repairs already choose the correct narrower shape.
  The mismatch explains why nine schema-admitted findings required native repairs.
- **Text repair cannot reconsider a wrong decision.**
  `specification_support_repair.merge` updates only the authorized text or evidence.
  It cannot replace an existing finding's substantive decision. That is deliberate
  current authority, not an accidentally missing retry.
- **Semantic actionability remains unchecked by mechanical text validation.**
  `validText` establishes bounded, nonblank text; `clarification_preparation` formats
  questions and evidence. Neither proves that the question identifies a real gap.
  The generic repair wording also asks for a missing decision “and expected answer
  format”; observed repairs ask the user to specify the format instead of providing it.
- **The retained run followed its admitted negative findings.**
  `required_authority.resolve` routes `unsupported` to a clarification. Safe
  false-conflict repair requires `candidate_omission` plus a validated producer
  location. This run never supplied that diagnosis.
- **The incomplete renderer exposes the consequence.**
  It intentionally emits only eligible business/scope claims. Making it print
  conflicting claims as supported would bypass the evidence contract.

The existing prompts already say to retain compatible overlap, distinguish kinds
from conflicts, review source meaning, and challenge false conflicts. Adding the
same warnings again is not an evidence-based remedy.

### What this analysis does not establish

- It does not establish why the model internally chose a false conflict, that
  temperature caused it, or that a larger model/reasoning setting will fix it.
- It does not establish context clipping: the inspected requests retain the source
  and relevant claims. High token use alone is not clipping evidence.
- It does not show a missing message stack, broken deterministic JSON assembly,
  token-budget exhaustion or lost source bytes.
- It does not show that the principle assessment failed. That assessment was not
  reached. Principle capture/configuration is distinct from assessment execution.
- It does not prove that an extra review will be correct. Semantic improvement
  requires controlled measurement and the complete live path.

The existing false-conflict regression in
[`specification_generation_test.zig`](../src/specification_generation_test.zig)
supplies a conflict-subject `candidate_omission` and `reconciliation_conflict` beside
supported findings. It proves that selected repair case; it does not cover
feature-level loss attribution, mixed findings or live recognition accuracy.

**Additional routing gaps confirmed by code inspection:**
[`required_authority.reconcile`](../src/domain/required_authority.zig) gives
`needs_user` precedence over candidate defects, and `supportedOmission` requires
the overall result to be `invalid`. Separately,
[`source_omission.select`](../src/domain/source_omission.zig) rejects the first
unlocalized omission before considering a later localized one. Thus a valid repair
can be bypassed by another finding. These are recovery-path gaps, not claimed events
of the retained run, which never supplied a localized omission. D4 defines the
decision required before promising complete recovery.

## 5. Decisions that must remain explicit

### D1 — Initial/insertion finding shape

**Pending; not approved by this documentation request.**

[The recorded R42 decision](IMP_001.md#r42-follow-up--question-contract-conformance)
already identifies the constraint: the shared schema compiler supports disjoint
`oneOf` objects distinguished by `kind`; the current flat `decision` enum cannot
express decision-dependent question presence in that schema subset.

Recommended proposal: represent the source finding as a closed discriminated
result using the existing wire convention. Require `detail` and `question` in
negative variants; forbid `question` in positive, applicability and candidate-loss
variants. The discriminator is the decision, not a second echoed decision field.
Reuse shared field definitions and the existing model codec. Do not extend the
schema language with arbitrary conditional validation for this one contract.

Before implementation, settle the exact native/wire representation and its shared
source/principle accessors in the focused §12.7 amendment. Keep retained-verdict
repair shapes narrow. Remove the superseded source wire shape and its readers;
add no alias or dual decoder. If persisted types change, amend their versioned
contract and reject the superseded representation rather than migrating it silently.

**Recovery trade-off:** a missing question in the initial review would now reject
before native collection. The existing protocol correction resubmits the complete
assigned review, using its assignment allowance; today's native repair replaces
one finding's text under its defect allowance. Otherwise correct entries are
resubmitted rather than retained by an atomic merge. Selected insertion/repair
requests still correct only their assigned response. D1 approval must cover this
scope change; unchanged accounting owners do not imply unchanged retry granularity.
Test changed/dropped siblings and failures moving between findings. Do not add a
partial parser, sibling-merging correction path or another counter to hide the trade-off.

This closes a mechanical mismatch. It cannot make a well-formed false negative true.
Protocol correction must not be used to evade the separate verdict-authority rule.

### D2 — Reassessment of a structurally admitted source finding

**Not approved. The earlier explicit user decision retained verdict authority.**
See [R44](IMP_001.md#r44-delivery--selected-schema-fidelity-and-omission-diagnostics)
and [§22.1](../design/contracts/22-repair.md#221-definition-of-atomic).

The default rollout preserves that decision. Initial task/evidence improvements
and measurement can proceed without introducing verdict rewriting. If an admitted
false negative must be reconsidered automatically, obtain a new explicit amendment;
do not disguise it as question repair, JSON correction or formatting.

The smallest proposal to evaluate is a bounded reassessment of a selected source
finding that proposes a new human clarification, through the existing review and
runner owners:

- Use that typed outcome as the trigger across source domains, not wording,
  fixture IDs, model names or a native guess that the model is wrong.
- Bind the original assignment, current source/candidate dependencies, original
  finding and origin; retain the earlier response as historical evidence.
- Permit an initial proposed maximum of one semantic reassessment per stable
  finding/dependency scope, subject to approval. Configure it through existing
  runner-owned limits; retain existing protocol-correction bounds and token charging.
- Accept any justified existing result, including a genuine negative. Do not vote,
  repeat until positive, infer progress from different wording, or reset the limit
  when the decision alternates, an unrelated target is repaired, or derived IDs and
  revisions are renewed. Freshness bindings must not become a retry-reset mechanism.
- A candidate-loss result still needs a unique authorized producer and rebuilding.
  A positive finding cannot clear a forced candidate defect or bless conflicting claims.
- Define an explicit terminal outcome for inconclusive reassessment without an
  identifiable user decision. It must not fabricate a question or completion.
- Amend §12.7/§16.4/§17/§22.1 together as applicable, including exact admission,
  exhaustion and freshness rules, before implementing the additional authority.

This is a decision proposal, not a selected new mechanism or a promise of success.
If declined, retain the current boundary and report any remaining live semantic
failure honestly. An approved comparison of configured model profiles is another
experiment; it is not an automatic fallback or established solution.

### D3 — Diagnostic evidence admission

**Pending contract decision; this documentation update does not approve it.**

Define a legal representation for feature/candidate loss attributed to an existing

[`specification_support_evidence`](../src/domain/specification_support_evidence.zig)

Record the focused §12.7/§16.4/§22 amendment before changing admission. Apply the

collection and persisted validation. Packet construction projects validator-owned
choices; it must not select citations for the model or create another evidence
policy. Cover cases where every business claim is classified as conflicting, plus
unrelated source domains and wrong/stale targets.

### D4 — Mixed findings and repair selection

**Pending routing decision; independent of optional verdict reassessment D2.**

Decide whether independently authorized candidate repairs precede a clarification
pause, and how localized and unlocalized defects coexist. Specify the shared typed
outcome and deterministic target selection for their combinations, including genuine
gaps and administrative/upstream blocks. Do not silently change outcome precedence
or discard an unlocalized defect to reach publication.

Keep continuation in `required_authority`, producer selection in `source_omission`,
and execution/rebuilding in the existing runner and compiled transitions. Record
the affected §16.4/§17/§22 amendments before implementation; a Spec-only YAML branch
cannot substitute for this shared contract. Every accepted repair must rebuild
affected dependents and reassess all findings. Genuine gaps remain unresolved until
their authority is supplied; source/target ambiguity never grants repair authority.

## 6. Phased rollout

### Phase 0 — Capture the complete regression and baseline

**Can proceed under existing authority.**

1. Preserve the minimal failing input/response sequence in existing test fixtures:
   compatible overlap across content kinds, false dispositions/conflict, nine
   unsupported findings without questions, text repairs, and the clarification exit.
   Keep raw malformed-prefix evidence separate from admitted normalized candidates.
2. Add unrelated representatives, such as loan renewal plus return-date output,
   rather than only changing the greeting text. Include genuinely incompatible
   source requirements and a genuine missing business decision.
3. Exercise real packet construction, compiled schema selection, collection,
   authority routing and renderer preparation using fake narrow ports. Preserve
   current behaviour as diagnostic evidence, not a desired nine-question outcome.
   Include feature-level conflict loss and mixed localized/unlocalized/gap findings
   in different orders; do not give every sibling a supported finding by construction.
4. Record source/schema/prompt identities, request bytes, provider usage and native
   repair counts. Mark all replay tests as offline; none substitutes for live E2E.

**Exit:** reproducible evidence distinguishes protocol failure, malformed review,
candidate loss and a real source gap. Changed expectations identify the applicable
§5 decision; no permanently skipped test or weakened assertion is introduced.

### Phase 1 — Align initial review schemas with native question rules

**Depends on Phase 0 and D1 approval.**

1. Implement the approved finding representation in the canonical support schema
   and existing native/model-codec boundary. Share common definitions rather than
   copying full subtrees for every decision.
2. Apply it to initial source review and missing-finding insertion together.
   Check source and candidate-support review, applicability, protocol correction,
   selected text/evidence repairs, debugger inspection and stored evidence admission.
3. Keep native text, evidence, exact-set, source freshness and loss-location checks.
   Schema success never authorizes semantic support or selects evidence.
4. Remove obsolete optional-everywhere source shapes and superseded tests/readers.
   Preserve the distinct no-question principle contract.

**Exit:** every negative initial/insertion response missing `question` rejects at
schema admission; forbidden questions reject for other variants. Selected native
repairs preserve siblings; whole-review corrections exercise D1's scope trade-off,
full validation and exact assignment accounting, including errors moving between
findings. Demonstrate actual compiled request shapes and measure repair traffic
and content drift; do not claim schema conformance resolves false conflicts.

### Phase 2 — Make the existing source review assess the right evidence

**Depends on the baseline and D3 for admission changes; does not require D2.**

1. Apply D3 through the shared evidence and loss owners for every subject: feature,
   signal, conflict, token, entity applicability and candidate field. Align request
   guidance with admission/readback while preserving positive-output provenance.
2. Derive displayed legal loss targets/evidence choices from those same rules.
   Prove feature-level conflict attribution can pass both evidence admission and
   loss validation; source-only evidence must not bypass exact conflict joins.
   Do not ask the model to invent an owner, ID or permitted repair scope.
3. Simplify current task/guidance presentation so source sufficiency is assessed
   from meaning, not the presence of prewritten title/story/AC/FR fields. Retain
   original source once, derived claims and the relationship under review. Replace
   redundant prose; do not add another summary call or duplicate policy assessment.
4. Preserve legitimate `not_applicable` choices under existing native rules.
   Absence of business entities is not automatically a missing user decision, and
   absence of a timestamp format does not authorize inventing one.
5. Test the extraction contributor: business behaviour repeated as technical
   content must not imply conflict. Keep classification semantic; no lexical
   deduplicator, universal “overlap is compatible” rule or change to precedence.
   In the existing extraction guidance, prefer independently meaningful claims
   while preserving coupled conditions. Test grouped and separate representations;
   do not add a sentence splitter, require one claim per source line, or prescribe
   a fixture-specific claim count. Measure the effect rather than promising it.

**Exit:** correct diagnoses are representable and admissible without weakening
positive provenance. Packet, repair and readback tests enforce the same rule and
reject unsafe attribution. Live recognition remains a Phase 6 measurement; prompt
wording alone is not conformance evidence.

### Phase 3 — Complete shared routing and candidate repair

**Depends on D3/D4 for the revised recovery route; D2 remains separately optional.**

1. Implement D4's approved mixed-outcome and target-selection contract through its
   existing owners. Cover localized defects beside genuine gaps and unlocalized
   defects, including different orders and blocking outcomes. Retain every finding;
   never convert an unsafe candidate defect into a user question or success.
2. Prove the existing coupled repair when review supplies
   `candidate_omission` with `reconciliation_conflict`: authorize the exact coupled
   disposition/conflict group, merge with old-value/revision checks, rebuild missing
   signals and coverage, and rerun current support review.
3. Cover both pre-generation and post-generation discovery. Invalidate dependent
   content/reviews/assessments through declared action dependencies and the runner.
   Do not reuse successful slices whose dependencies changed; retain unrelated
   siblings only while their exact dependency bindings remain current.
4. If D2 is approved, implement its selected reassessment through the existing
   packet, admission, repair/evidence and runner owners. Amend the existing selected
   finding operation only as authorized; do not add a second review authority,
   hidden model invocation or unbounded successor loop.
5. If D2 is not approved, keep admitted verdicts immutable and leave recovery from
   those false negatives explicitly unresolved. Successful text repair is not
   evidence that semantic recovery occurred.

**Exit:** every mixed case follows D4's approved outcome/selection contract. An
authorized repair rebuilds all affected dependencies before reassessment; unsafe
or stale attribution grants no repair, and unresolved defects/gaps retain their
required outcome. If enabled, reassessment exhausts its approved allowance while
resolved independent work can continue within the global token budget.

### Phase 4 — Complete actionable questions and downstream integration

**Depends on the selected review/routing contracts; preserve publication authority.**

1. Use existing fields: `detail`/`why_required` for known facts, preconditions and
   why a choice is needed; `question` for the precise choice and expected answer.
   The request must provide the answer format, not ask the user to design it.
2. Apply that contract to initial findings, insertion, selected question repairs
   and generation-created needs. Give field-specific diagnostics for mechanically
   missing/invalid content. Do not claim a nonempty-string check proves actionability.
3. Keep formatting pure. It may select existing cited excerpts, remove contained
   duplicate quotations and reference the full sidecar when needed. It must not
   infer a gap, invent an answer, rewrite a verdict or combine unrelated subjects.
4. A concern that identifies no missing decision stays at the review boundary;
   use only the approved handling from Phase 3. Do not replace it with a generic
   “describe this requirement” form. Semantic assessment remains model-assisted.
5. Verify complete generation and principle assessment after source support recovers.
   The current principles include greeting-only restrictions while the story asks
   for UTC date/time. Under ADR 0015, preserve clear intent and record the cited
   policy conflict as a mandatory Plan obligation. Do not silently waive principles,
   remove the UTC requirement or create premature Plan clarifications.
6. Preserve both output routes: complete supported AC/FR content renders through
   the existing specification renderer; genuine gaps render the validated incomplete
   projection plus actionable forms. Neither route bypasses unrepaired validation.
7. Validate completed-state source review/principle evidence and exact extraction
   contract on readback. Pending state currently stores references and clarification
   bindings, not a complete source-review transcript: test its actual contract and
   fresh-run rebuilding without pretending that historical prose is current proof.
   Preserve user-closed forms and stable subject identities.

**Exit:** users are asked for a decision the supplied source does not already answer.
Genuine gaps retain current facts, a concrete question and a usable answer format.
Policy conflicts and business gaps remain distinct. No renderer-only semantic fix.
