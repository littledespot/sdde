## Frozen inputs and dynamic downstream requests

The official `zig build test-specification-generation --summary all` entry calls
[the preparation fixture](../../../src/test_fixtures/source_review_handoff_calibration.zig).
It renders all review packet/edit/provider-request bytes to
`.zig-cache/source-review-handoff`, runs native handoff probes, then checks them
byte-for-byte against this directory. [preparation.json](preparation.json) pins
the panel, schema, prompts, preparation/native-admission code, settings, scorecard
and review request hashes. These checked-in files are projections of canonical
cases and production builders; they are not runtime fallback assets. Change
canonical inputs/code, regenerate through the official target and explicitly
review a new freeze; never patch a projected request.

Loss requests are **not** frozen from expected obligations or oracle attribution.
They cannot exist until an exact reviewer receipt is admitted. Future separately
approved review receipts may be retained locally as
`.zig-cache/source-review-handoff/<case>.review.receipt-<1|2>.json`. Their closed
shape is:

```json
{
  "input": "exact frozen review packet body",
  "origin": {
    "trial_id": "<case>-review-<1|2>",
    "parent_run": "source-review-handoff-frozen-panel",
    "parent_call": "production-source-review-assignment",
    "replay_run": "actual separately approved run",
    "replay_id": "actual captured response ID",
    "request_sha256": "SHA-256 of exact frozen provider request bytes",
    "response_sha256": "SHA-256 of exact response_bytes"
  },
  "response_bytes": "exact captured model_text bytes"
}
```

[handoff.parent.json](handoff.parent.json) is a diagnostic panel binding, not a
native provider-operation origin. Store raw provider HTTP/body evidence and usage
separately and verify the model-text extraction against it. Do not paste a raw
provider envelope in place of model text or alter that text to repair meaning.
The receipt owner rejects missing/unknown fields, wrong input, trial/repetition,
parent, request hash, response hash or blank replay references. Existing
`model_envelope` owns any approved opening-prefix normalization; the original
response bytes and hash remain retained.

After receipt admission, `Source.collectFocused` reconstructs the current native
review and validates its evidence. Supported, genuine-gap, inconclusive, malformed
or rejected output produces no loss request. Only the actual admitted
`candidate_omission` drives `Source.comparisonAssignment` and `packetForLoss`.
Actual detail, `missing_obligation` and source IDs pass unchanged. A mechanically
admissible but false obligation also passes unchanged and is scored as harmful
discovery; preparation never substitutes an expected obligation to improve it.
The dynamic cache report identifies the exact receipt, normalization, full loss
assignment and loss request; request filenames include the response hash.
Historical cached artifacts do not supply authority for another receipt.
The native summary retains the actual selected finding and rejection diagnostic
independently of loss eligibility, including supported, gap and uncertain values.

The prior review entries required to reach an isolated selected assignment are
explicitly **MOCK supported scaffolding**, admitted through the native collector.
They are not evidence that a complete production workflow succeeded. Replayed
receipts never manufacture native call/attempt identities: native origins remain
null and `native_origin_available=false`. Authentic execution-local origins and
repair permits must come from the connected production path.

## Admission, scoring and limits

Offline probes cover receipt hashes and closed fields, foreign/stale bindings,
unchanged incorrect reviewer values, source occurrences, complete comparison
membership, missing/duplicate/foreign comparison IDs and foreign spans. A complete
supplied uncertain response is natively admitted, retains the actual finding and
ends with unresolved attribution; this is mock mechanical evidence, not semantic
accuracy. No one-view diagnostic or oracle loss response substitutes for the
current full comparison assignment.

Score a faithful individual finding separately from complete coverage of all
omitted duties owned by the assigned purpose. A faithful partial finding may pass
faithfulness and still miss another duty. Record that missed coverage without
replacing or extending the actual reviewer finding in the downstream request.
Combined findings must retain their complete assignment and be judged against
every duty in that actual combination; do not split requests or force a single
historical owner to improve the result.

[scorecard.template.json](scorecard.template.json) is unscored. Independently judge
discovery/detail/obligation/source faithfulness, then attribution and its native
admission. Record every scheduled review trial, including unsent, malformed or
rejected outcomes; conditional loss trials include only actual admitted omissions.
Record sent/unsent status, exact actual usage, normalization and transport versus
end-to-end timing separately. Disclose model-assisted assessment and resolve
disputes before a qualification claim. Assess conditions, negation, strength,
occurrences and user-choice reversals by meaning, without an exact prose test.

Once a separately approved complete loss response exists, pass it through the
same current `Source.collectLoss` / comparison admission used by the mock probes;
retain the exact response receipt and current assignment. Native admission and
faithful attribution are separate scores. Score judgment-by-judgment comparison
meaning, explanation adequacy and citation completeness and relevance separately
from final attribution. This
production-only panel prepares qualification; it does not establish improvement
over a comparison arm. The connected production repair owner
alone can establish eligible local or upstream repair, denial, merge/dependent
revalidation/full-candidate validation and publication eligibility. This panel
does not infer those permissions from an attribution label. Until authentic
connected evidence exists, leave those scorecard fields unassessed. Failed,
blocked, denied, unresolved and successful outcomes stay distinct, and harms are
reported separately from discovery or repair benefits.
