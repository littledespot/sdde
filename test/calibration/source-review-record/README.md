# Coherent AC-record source-review preparation

This panel prepares a comparison of three current singleton requests with one
coherent record request. Both arms retain the same native Given, When and Then
requirements, field tasks, assessment scopes and evidence rules. The separate
AC-collection requirement is unchanged. Source and policy review remain separate.

Phase 6 refreshes the offline preparation's native collector/repair dependency
pins. All packet, edit and provider-request bytes remain unchanged; no historical
live result is relabelled and this refresh grants no dispatch approval.

The six assignments contain five development cases and one reserved qualification
case. The captured launch record retains its actual canonical candidate; it tests
the reported temptation to demand consequent behavior from the Given field.
Distributed renewal conditions, a genuine missing condition, an unrelated
prohibition, and two distinct missing field duties provide development controls.
The reserved parcel assignment changes a continuing clearance condition into an
automatic timeout. Expectations describe meaning and roles rather than exact
answer text. The captured case does not settle whether its launch-state field adds
an unsupported restriction; assess that question separately from false omission
of consequent behavior.

Each arm has two repetitions: 24 record-level trials, 72 required field findings,
36 singleton review sends and 12 record review sends. Up to 72 conditional loss
sends can follow actual admitted omissions, for an absolute ceiling of 120 physical
sends and 500,000 actual input-plus-output tokens. Neither ceiling authorizes a
send. Retries, correction, repair dispatch, model judges and E2E are excluded.
The pinned setting is Bedrock `openai.gpt-oss-20b-1:0`, region `ap-southeast-2`,
low reasoning, temperature 0.1, native schema and `max_completion_tokens=16384`;
seed and top-p are absent.

`cases.json` and `scorecard.template.json` are canonical preparation and scoring
inputs. The official `zig build test-specification-generation` entry generates
72 packet/edit/provider-request projections and `preparation.json` beneath
`.zig-cache/source-review-record/`, then compares them to this directory. A first
preparation run fails on absent frozen projections after mechanical checks. Freeze
only those official generated bytes; subsequent source/schema changes require
official regeneration and review. No calibration model call or network launcher
is present. The paired checks verify unchanged field obligations and common
evidence, a single shared record, exactly three schema entries and rejection of a
partial schema response. They do not prove semantic quality.

Any later live run requires separate approval of this fixed plan. Retain the exact
request/response receipts and distinguish each singleton operation from the one
record operation. Use the existing strict receipt, model-envelope and native
Source collector owners; do not fabricate provider-operation origins from replay
labels. A grouped response must pass complete membership and each field's native
evidence admission. Its actual values then remain unchanged. An omission can
produce only its complete current preservation comparison assignment, one defect
at a time. No downstream request is fabricated or frozen from expected obligations.

Score complete field coverage, joint meaning, cross-field interference, false
findings and condition/negation/strength preservation separately. A faithful
identified defect does not establish that every omission was found. Score every
comparison judgment, explanation adequacy, citation completeness and relevance;
judge attribution for the actual duties identified. Diagnostic localization is
distinct from native local/upstream repair eligibility, denial, execution and full
revalidation. Include malformed, partial, rejected, uncertain and not-sent trials
in the scheduled denominator. Report actual usage and measured transport and
end-to-end timing separately. Fewer requests are a cost hypothesis, not a semantic
improvement claim. All scorecard values remain unscored until actual outputs and
assessments exist. Historical calibration freezes are not promoted by this panel.
